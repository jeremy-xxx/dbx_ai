# 阶段 7：效果监控

> **目标**：真实寿命出来后，检查模型在新批次上的真实表现，找出误差变大的原因，并决定是否需要再训练。
> **notebook**：`07_monitoring.py` **耗时**：约 45 分钟

---

## 7.1 为什么要监控
模型在测试集上的误差，只说明它在**和训练数据相似的数据**上表现如何。上线后遇到的新数据可能不一样：换了供应商批次、换了快充策略、测试设备重新校准……这时误差会变大，而且**没人会主动告诉你**。

本项目的 batch3 晚近一年开始，快充策略范围也不同，正好模拟这种情况。

## 7.2 三项检查

**① 预测误差：新批次 vs 测试集**

```
error_ratio = 新批次 MAPE ÷ 上线时的测试集 MAPE
```
超过 `DRIFT_ALERT_RATIO`（默认 1.5 倍）就告警。同时统计真实寿命落在 `[predicted_low, predicted_high]` 范围内的比例：范围设得合理的话，这个比例应该比较高。

**② 质检决策质量**
对质检最关键的是**漏检**：真正的短寿命电芯被标为 `normal` 放行了。notebook 用交叉表展示决策和真实情况的对应关系：

| | 实际短寿命 | 实际正常 |
|---|---|---|
| 标为 short_life / borderline | ✅ 抓到了 | 多做了检测（误报，代价小） |
| 标为 normal | ❌ **漏检**（代价大） | ✅ 正确放行 |

**③ 特征漂移：新批次和训练数据像不像**
只检查模型实际用到的特征（来自 champion 版本的 `features` 标签）：

| 指标 | 怎么算 | 经验阈值 |
|---|---|---|
| 标准化均值差 | (新批次均值 − 训练均值) ÷ 训练标准差 | 绝对值 > 0.5 值得注意 |
| PSI（群体稳定性指数） | 按训练集的分位数分箱，比较两边每个箱子里的样本占比 | < 0.1 稳定；0.1–0.25 轻微漂移；> 0.25 明显漂移 |

如果误差变大，同时某个重要特征的 PSI 很高，基本可以判断：**新批次的电芯“长得”和训练数据不一样**，模型没见过这种情况。

## 7.3 监控表
每次运行在 `model_monitoring` 表追加一行：模型版本、新批次误差、误差倍数、范围命中率、漏检数、漂移最大的特征、是否告警。长期运行后，就能看出模型效果的变化趋势。

## 7.4 告警之后怎么办：再训练闭环

```
监控告警 ──► 把新批次的一部分加入训练集 ──► 重跑 03 → 04 → 05（闸门） ──► 06 用新 champion 重新打分 ──► 07 再检查
```

练习 1 带你完整走一遍：在 `01_ingest` 把 batch3 一半的电芯改为 `train`，依次重跑。观察两件事：新模型能不能过闸门？batch3 剩下的电芯误差有没有下降？

这就是 MLOps 的核心闭环：**训练 → 上线 → 监控 → 发现问题 → 再训练**。
